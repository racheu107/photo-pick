# 평가 흐름 단순화 — 0.2.21 d15 / 2026-10-12

사용자 요청: 평가하면 다음 미평가로 이동, 평가 버튼 조금 확대, 최종 사진 고르기 제거, 확대 복귀/유지 사례 조사.

## 적용

- 평가 확정 후 현재 촬영일 범위의 다음 미평가 사진으로 이동한다. 뒤쪽 미평가가 없으면 앞쪽 남은 미평가를 찾고, 모두 평가하면 평가 결과를 연다.
- 아래 드래그도 다음 미평가로 이동한다. 매우 좋음은 아래로 평가해도 유지한다. 아래 드래그의 인접 사진 미리보기도 실제 이동 대상과 맞췄다.
- 기존 재탭으로 평가 해제하는 동작은 유지하며, 미평가로 해제할 때는 현재 사진에 머문다. 매우 좋음 재탭으로 좋음이 되면 평가 확정으로 취급하여 이동한다.
- 평가 버튼 높이 48→56 CSS px, 별로/좋음 그룹 128×56→144×64, 매우 좋음 버튼 56×56, 평가 아이콘 24→28(매우 좋음 22→26). 현재 평가 초기화 버튼은 48 유지.
- 최종 N장·베스트샷·A/B 비교 모듈/진입 버튼/패키지 자산 제거. 이전 최종 선택 기록을 사용하지 않고 평가 등급 범위로 다운로드한다. 평가 자체는 보존한다.
- 확대는 연구 결과를 보고 결정하는 요청이므로 ‘모든 손가락을 떼면 복귀’를 유지했다. 추천안은 `zoom-ux-research-2026-10-12.md`에 기록했다.
- Android와 로컬 웹의 평가/제스처 소스를 맞추고 로컬 웹에서도 제거를 반영했다. 공개 릴리스·사이트 배포는 하지 않았다.

## 검증

Android assembleDebug/lintDebug 성공. 완성 APK 자산을 소스와 비교했고 best-shots 자산이 패키지에 없음을 확인했다. 완성 APK에서 추출한 웹 자산으로 아래 검사를 재실행해 통과했다.

- 별로·좋음·매우 좋음 평가 후 미평가 이동, 이미 평가한 사진 건너뛰기.
- 빠른 연속 탭 중복 방지, 재탭 평가 해제 시 현재 위치 유지.
- 마지막 뒤쪽에 미평가가 없으면 앞쪽 미평가로 이동, 모두 완료하면 평가 결과.
- 날짜 범위를 벗어난 사진에 평가·이동하지 않음.
- 아래 평가 미평가 이동, 매우 좋음 보존.
- 실제 브라우저 터치 핀치 후 원래 배율 복귀와 평가/사진번호 불변.
- 320×568, 390×844, 430×932에서 평가 버튼 최소 56×56, 사진·조작부 겹침과 가로 넘침 없음.
- d14 최종 선택이 남아 있는 저장 데이터를 불러와도 기존 평가 보존·등급 기준 선택 복원.
- 베스트샷 버튼·스크립트 없음, Android 저장 API에 등급 범위의 전체 대상 전달.
- 로컬 웹에서도 평가 후 이동과 기능 제거 확인.

실제 완성 APK를 Android 에뮬레이터에 업데이트 설치하고 네이티브 Bridge가 있는 WebView에서 사진 평가 → 미평가 이동 → 평가 결과를 다시 확인했다. 크기 56×56 이상, 평가된 다음 사진 건너뛰기, 제거된 버튼/스크립트, 등급 기준 다운로드를 확인했다.
