# 확대를 놓으면 복귀 vs 유지 — UX 사례 조사

조사일 2026-10-12. 공식 도움말을 확인한 사례 조사와 Photo Pick에 대한 설계 판단이다. 실제 사용자 실험 결과는 아니다. 이 조사만으로 확대 동작 코드는 바꾸지 않았다.

## 결론

Photo Pick의 기본 핀치는 **같은 사진을 보는 동안 확대·이동 위치 유지, 다음 사진으로 가면 전체보기로 초기화**를 추천한다. 사용자가 사진을 다시 전체로 보고 싶을 때 더블탭 또는 명시적 전체보기로 돌아가게 한다.

이번 사용자 결정으로 평가 후 다음 미평가 사진으로 자동 이동한다. 따라서 평가하면 다음 사진이 전체 구도로 나타나는 흐름을 만들 수 있어, 손을 놓자마자 매번 확대를 없앨 필요가 줄어든다. 이는 제품 맥락에 따른 추론이다.

## 사례와 증거 범위

| 사례 | 공식 문서에서 확인한 동작 | Photo Pick에 대한 시사점 |
| --- | --- | --- |
| iPhone 기본 제스처 | 두 손가락 벌리기/모으기, 사진 더블탭 확대·다시 더블탭 축소 | 핀치와 확대/축소 토글이라는 익숙한 복귀 경로를 참고할 수 있음 |
| Lightroom mobile | 두 손가락 핀치 확대·축소, 누르고 있기 전후 비교 | 확대 조절과 잠깐 비교하는 동작을 분리. 이 문서는 사진 편집/보기에서 손을 떼는 순간의 확대 상태를 직접 명시하지 않으므로 ‘모바일에서 항상 유지’의 단독 증거로 쓰지 않음 |

## 두 방식의 예상 장단점

| 상황 | 손을 놓으면 복귀 | 같은 사진에서 확대 유지 |
| --- | --- | --- |
| 눈·초점을 잠깐 확인 | 별도 복귀 동작 없이 전체 구도를 다시 봄 | 확대 후 평가까지 화면을 계속 확인 가능 |
| 눈 → 다른 얼굴 → 디테일 연속 확인 | 손을 떼면 위치가 사라져 다시 확대해야 함 | 손을 편하게 다시 잡고 이동 가능 |
| 한 손 조작·반복 작업 | 두 손가락으로 계속 잡아야 확대가 유지되어 피로 가능 | 핀치 후 한 손가락 이동·버튼 평가 가능 |
| 다음 사진 넘기기 | 복귀 뒤 제스처 넘김이 바로 가능 | 확대 중 드래그와 넘김을 구분하고 복귀/이동 경로 필요 |
| 구도 전체 재확인 | 자동으로 전체가 나타남 | 더블탭/전체보기 필요 |
| 익숙한 제스처와 예측 | 핀치를 뗄 때 원복되는 규칙을 처음 알려야 함 | 핀치 후 크기가 남는 사용 모델과 더블탭 왕복을 적용 가능 |

위 표의 편의·피로·예측 가능성은 실제 측정 수치가 없는 UX 가설이다. 순간 복귀도 빠른 전체 구도 판단에는 유효하므로 잘못된 방식이라고 단정하지 않는다.

## 추천 동작 명세 (미구현 제안)

1. 두 손가락 핀치 후 손을 떼어도 같은 사진의 확대·위치를 유지한다.
2. 확대 상태의 한 손가락 드래그는 사진 내부 이동만 수행한다. 넘김·아래 평가로 해석하지 않는다.
3. 더블탭 또는 전체보기로 기본 배율에 복귀한다. 더블탭 신규 확대의 중심점과 배율은 별도 검증한다.
4. 확대 중에도 사진 밖 평가 버튼을 사용할 수 있다. 평가하면 다음 미평가 사진의 전체 구도로 이동한다.
5. 상단 이전/다음 버튼은 확대 상태에서도 이동 수단으로 제공한다. 새 사진은 항상 전체보기로 시작한다.
6. 화면 이동·초기화·앱 전환 시 포인터 상태를 정리하여 잘못된 평가나 드래그를 방지한다.

현재 코드의 isPhotoMotionBusy는 확대 상태도 포함하므로, 유지 확대를 적용한다면 ‘확대 유지’와 ‘진행 중인 손가락 조작’을 분리해야 한다. 그렇지 않으면 확대를 유지한 상태에서 평가 버튼이 막힐 수 있다. 다음 구현은 단순히 포인터 해제 시 reset을 지우는 것으로 끝나지 않는다.

## 실제로 비교할 과제

- 한 사진에서 눈과 초점을 확인하고 바로 좋음 평가하기.
- 단체 사진의 서로 다른 얼굴 세 곳을 확인하기.
- 확대 후 전체 구도를 다시 확인하기.
- 확대 상태에서 다음 사진으로 이동하기.

재확대 횟수, 손을 계속 유지하는 부담, 잘못된 넘김/평가, 전체보기 복귀 발견 여부를 비교한다. 선호 응답과 실제 행동을 구분하고 아직 성능·만족도 개선을 확정하지 않는다.
