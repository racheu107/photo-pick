# Photo Pick 디자인 APK 반영 준비 회의

후속 진행: 사용자의 ‘진행’ 요청으로 별도 앱 d1 구현과 APK 빌드를 완료했다. 최신 설치 파일은 design-preview/releases/PhotoPick-DesignPreview-0.2.7-d1.apk, 검증 결과는 design-preview/verification/검증결과-d1.md 및 releases/release-manifest.json이다. 아래 준비 시점의 환경 미설치·UI 미구현 내용은 당시 기록이며 현재 상태가 아니다. 실제 휴대폰 테스트는 아직 하지 않았다.

일자: 2026-10-09 (한국 시간)
참여: 총괄 에이전트, 디자인 담당, 인터랙션·QA 담당, Android·릴리스 담당. 각 담당이 현재 소스와 최신 결정을 확인하고 총괄에게 제안, Android·QA의 상호 의존성을 조율했다.
스킬: 사용자 허락을 받은 karpathy-guidelines. 최소 변경·원본 분리·검증 기준을 적용했다.

## 결과와 현재 단계

현재 운영 기준은 versionName 0.2.7, versionCode 10, com.photopick.app, Git commit 61ae5b46c86e10e74588609cae430d748ca58745이다. Git 작업 트리는 변경 없이 확인했다.

0.2.7 소스·기존 APK·기준 커밋 기록의 별도 백업과 새 디자인 소스 복사본을 준비한다. 원본 github-upload에는 작업하지 않고 design-preview/source에서만 변경한다. 새로운 디자인 UI와 새 APK는 아직 구현·생성하지 않았다. Git 전체 이력 묶기는 Google Drive의 디스크 대기로 중단했으며 전체 이력은 이번 백업에 포함하지 않는다. 현재 버전의 내용 복원은 소스 스냅샷으로 가능하다.

새 작업 복사본에는 설치 분리만 먼저 반영했다: applicationId com.photopick.app.designpreview, 표시 이름 Photo Pick 디자인 테스트, AppUpdater.check의 자동·수동 조회 전에 designpreview 패키지 차단. namespace 및 Java 클래스 위치는 유지한다. 새 디자인 작업 복사본의 버전 번호는 아직 0.2.7/10이며 운영 업데이트 버전을 올린 것은 아니다. 이 준비 변경은 컴파일 전이다.

## 백업과 작업 위치

- 원본: github-upload
- 고정 백업: backups/0.2.7-before-design-2026-10-09/source
- 원본 APK: backups/0.2.7-before-design-2026-10-09/apk/PhotoPick-0.2.7-debug.apk
- 휴대용 압축본: backups/0.2.7-before-design-2026-10-09/baseline.zip
- 무결성 기록: backups/0.2.7-before-design-2026-10-09/manifest.json
- 변경 작업 전용: design-preview/source
- 백업 생성 도구: tools/prepare-design-backup.ps1
- 소스 복원 도구: tools/restore-design-baseline.ps1

백업에는 추적 소스와 현재 기획 문서·시안을 보관한다. 빌드 산출물·Gradle 캐시·IDE 캐시·회사 PC용 local.properties·서명키는 포함하지 않는다. APK 파일과 키는 서로 다른 것이며 APK 백업으로 서명키를 복구할 수 없다. 복사본과 압축본의 파일 해시를 원본과 비교한다. 기존 Git 이력은 원본 github-upload/.git에만 남고 백업에 포함하지 않는다.

## 설치 분리와 원복

첫 디자인 검증은 별도 applicationId로 병행 설치한다. 기존 0.2.7을 삭제하거나 덮어쓰지 않는다. 테스트 앱은 폴더 접근을 새로 승인하고 별도 평가 기록을 사용한다. 기존 평가가 자동으로 옮겨지지는 않는다.

휴대폰 원복: 기존 Photo Pick 앱을 실행한다. 필요하면 디자인 테스트 앱만 삭제한다. 기존 앱 데이터와 SD 원본은 테스트 앱과 분리된다. 갤러리에 테스트 앱이 저장한 파일은 앱 삭제와 별개이므로 중복 저장을 별도로 확인한다.

소스 원복: 프로젝트 루트에서 `& '.\tools\restore-design-baseline.ps1'` 실행. 새 restored-0.2.7 디렉터리에만 복원하며 기존 디렉터리를 덮어쓰거나 삭제하지 않는다. 같은 이름이 있으면 중단한다. 다른 이름은 DestinationName으로 지정한다. 모든 복원 파일의 SHA-256을 검증한다. baseline.zip으로도 소스·APK를 다른 PC로 옮길 수 있다. 전체 Git 이력이 필요한 경우 별도 백업이 필요하다.

운영 앱과 동일 패키지의 높은 버전으로 업데이트한 뒤 낮은 0.2.7 APK를 일반 설치로 덮어쓰는 것을 원복 방법으로 삼지 않는다. 삭제 후 재설치는 평가·폴더 권한 손실 가능성이 있다. 운영 업데이트를 만들려면 회사 PC의 기존 서명키와 인증서 지문 일치가 필요하다.

기존 업데이터는 android-vX.Y.Z-preview 및 테스트 릴리스를 탐지한다. 디자인 테스트 APK는 이 규칙의 태그/파일명으로 공개하지 않는다. 외부 테스트 배포를 따로 요청받으면 design-preview-* 태그와 PhotoPick-DesignPreview-* 이름을 쓰고 실제 격리를 검증한다. 이번 준비에서는 공개 릴리스·Git push·배포를 하지 않는다.

## 최종 구현 계약

- 기존 밝은 앨범·어두운 집중·사진 contain·사진 밖 평가바·상단 이전/다음/장수/결과 진입 유지.
- 작은 Undo, 별로/좋음 각각 독립 버튼, 매우 좋음 버튼. 아이콘 후보는 회전형 Undo·엄지 아래·하트·별. 상단 앨범 복귀는 Undo와 구별되는 chevron 권고. 아이콘 후보의 실제 선택은 구현 시안에서 확인한다.
- 버튼만으로 최초 평가·재평가·동일 재탭 해제가 가능하며 현재 사진에 머문다. 활성은 채움·배경으로도 표시한다. 매우 좋음/아주 좋음은 하나의 best 상태이며 앱 문구는 통일한다.
- 우 스와이프 이전, 좌 다음, 등급 유지·순환 없음. 아래는 best 보존, 나머지는 keep 설정 후 다음 순번. 마지막에서는 평가를 반영하고 머물며 결과 진입 제공.
- 사진 우상단 별과 하단 별은 같은 상태. 사진 프레임 실제 경계에 붙이고 가로·세로 사진 모두 확인.
- 드래그 중 방향별 가장자리 그라데이션과 아이콘·문구 예고, 손을 놓을 때 조건 충족 시 확정. 짧은 드래그·취소·대각선·경계에서는 잘못된 예고/실행 방지.
- 확대/두 손가락에서는 사진 팬·줌, 평가/넘김 차단. 기존 줌 복귀 규칙의 변경은 별도 확대 명세가 확정되지 않았으므로 이번 준비에서 추가하지 않는다.
- Undo는 최근 완료 행동의 평가·사진 위치를 복구하는 구현 권고. 탐색과 평가+자동이동을 구분해 기록한다. 취소·막힌 경계·동일 상태의 무변경 버튼 입력은 이력에 넣지 않는다. 큰 전체 평가 사본 대신 제한된 변경 이력을 사용한다.
- 첫 사용 시범과 재탭 취소·원본 삭제 없음 안내. 모션 감소에서는 큰 시범 대신 아이콘·문구를 제공한다. 기존 모션 안정성을 유지한다.

## 구현 순서와 수용 기준

1. 평가와 순차 탐색 분리: 현재 review-ui.update는 버튼도 다음 미평가로 이동한다. 버튼 머무름과 인접 순번 탐색으로 교정한다.
2. 상태 토글·best 보존·상하단 동기화: 평가4상태(unrated/skip/keep/best)와 각 입력을 교차 확인한다. 결과 개수와 저장 목록 일치.
3. Undo·저장 위치 정합성: before/after 사진 ID와 rating delta 기록, 구버전 저장 데이터 복원, 재시작 위치 보존.
4. 이미지 비동기 처리: 로드/디코드 후 탐색 commit. 실패 시 현재 사진 유지·이미 반영한 평가에 대한 Undo 유지. 이탈/뒤로가기 후 늦은 응답 무시.
5. 아이콘·코랄·제스처 피드백 적용: 세 화면 크기, 밝음/어두움/복잡한 사진, 가로사진 contain, 버튼 영역·화면 읽기 이름·모션 감소.
6. 격리 APK assembleDebug/lintDebug 및 test APK 빌드. 병행 설치 확인 후 사진 입출력·원본 SHA256·SD 분리·저장 실패를 검증한다. 빌드 통과를 실제 기기 테스트와 혼동하지 않는다.

핵심 입력 QA: 첫/끝/1장, 선택 날짜 비연속 ID, 아래와 각 버튼/별/Undo, 지연·실패·연타·취소·손가락 수 변경·줌·앱 재시작. 회귀 기준은 EXIF 날짜 범위, 원본 비율, 배경 고정 사진만 전환, Android 뒤로가기, 원본 갤러리 저장, 기존 평가 데이터다.

제외: 카드 스택·필름스트립·얼굴 자동 확대·스마트 추천·사진 위 큰 흰색 바·전면 블러·테마 전면 개편·원본 입출력 재설계·운영 업데이트 배포.

## 집 PC 빌드 환경 확인

- 필요한 구성: JDK17, Gradle8.9 wrapper, AGP8.7.3, SDK35.
- PATH의 Java는 1.8.0_301이고 JAVA_HOME은 비어 있다.
- 기존 local.properties가 가리키는 C:\Users\USER\AppData\Local\Android\Sdk는 존재하지 않는다.
- 기본 debug.keystore는 확인되지 않았다. 기존 APK 서명키 매칭도 미확인이다.
- 새 테스트 패키지는 새 개발키로 서명 가능하지만 JDK·SDK를 먼저 준비해야 한다. 운영 업데이트용 서명은 회사 PC의 기존 키 확보가 별도 필요하다.

따라서 백업·작업 분리·구현 계획 준비와 APK 빌드 준비 상태를 구분한다. 현재 환경에서 새 APK가 생성되었거나 설치 원복이 실행 검증되었다고 보고하지 않는다.
