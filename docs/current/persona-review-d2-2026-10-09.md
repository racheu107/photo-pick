# d2 평가 버튼 소비자 페르소나 시뮬레이션

2026-10-09, 사용자 후속 규칙 기준. 24세 여행 사진 초보와 32세 미러리스 사용자의 상황을 가정한 두 에이전트가 검토했다. 실제 참가자가 참여한 테스트가 아니며 여성 전체의 선호·성공률·소요 시간을 측정하지 않았다.

## 적용한 상태 전환

| 현재 상태 | 조작 | 다음 상태 / 표시 |
| --- | --- | --- |
| 미선택 또는 별로 | 매우 좋음 아이콘 | 좋음+매우 좋음 활성 |
| 매우 좋음 | 매우 좋음 아이콘 재탭 | 좋음만 유지 |
| 좋음 | 좋음 재탭 | 미선택 |
| 좋음 | 매우 좋음 아이콘 | 좋음+매우 좋음 활성 |
| 매우 좋음 | 좋음 재탭 | 미선택 |
| 매우 좋음 | 되돌리기 | 미선택, 현재 사진 유지 |
| 매우 좋음 | 별로 | 별로만 활성 |

아래 스와이프는 매우 좋음이면 그대로 유지하고 다음, 그 외에는 좋음으로 평가하고 다음이다. 좌우 이동은 평가를 변경하지 않는다. 별로 버튼 재탭은 미선택이다. 모든 평가 버튼은 최초 평가에도 사용할 수 있고 탭 후 현재 사진에 머문다.

## 페르소나 검토 결과와 반영

초보는 하트와 별이 함께 켜지면 ‘고른 사진 중 특별한 컷’이라는 관계를 이해할 가능성이 있지만 별 재탭·하트 재탭의 결과가 다르다는 안내가 필요하다고 보았다. 첫 안내는 X·하트·반짝임의 의미와 별 해제 후 좋음 유지, 하트 해제 후 모두 취소, 원본 삭제 없음을 설명하도록 변경했다.

경험자는 연사 비교 후 이전 사진에서 평가가 즉시 보이는 것을 중요하게 보았다. 각 등급의 왕복·재시작 표시를 실제 브라우저에서 검증하고, 선택 배경의 기존 160ms 색상 전환을 없애 즉시 밝은 회색 배경·짙은 아이콘으로 표시했다.

두 페르소나 모두 Undo가 매우 좋음일 때 ‘직전 행동 복구’가 아니라 ‘현재 사진 선택 초기화’라는 점을 위험으로 지적했다. 사용자 계약은 유지하되 해당 상태에서는 접근성 이름·툴팁을 ‘이 사진 선택 모두 취소’로 바꿨고 취소 후 짧은 안내를 표시했다. 다른 상태에서는 ‘마지막 행동 되돌리기’를 유지한다. 후속 평가 시 이전 취소 안내를 지워 상태와 문구가 어긋나지 않게 했다.

두 활성 아이콘이 사진 두 장으로 합산되지 않도록 결과에는 ‘선택 N장 · 그중 매우 좋음 M장’과 ‘선택 사진 전체 N장’을 표시한다. 내부 등급 best는 한 사진의 등급이며 저장 대상 사진 ID는 중복되지 않는다. 등급별 행에서 좋음과 매우 좋음은 서로 배타적인 집계다.

## 다른 버튼 계약

- 이전/다음과 좌우 스와이프: 선택한 날짜 범위에서 탐색, 평가 유지. 첫/끝에서 순환하지 않는다.
- 되돌아가기: 앨범 복귀, 평가 유지. 평가 취소와 구분되는 화살표 사용.
- 평가결과: 현재 집계와 저장 범위 확인. 미선택·별로는 저장하지 않는다.
- 좋음·매우 좋음·별로: 설정/변경/해제 후 현재 사진 유지.
- 확대: 두 손가락·확대 상태에서는 사진 팬만, 평가/넘김 차단.
- 마지막 사진에서 아래: 평가 반영 후 머물고 결과 확인 안내.
- 이어하기: 마지막 위치·선택한 날짜·평가 복원.

## 실제 검증과 남은 검증

브라우저의 상태 행렬·왕복·재시작·Undo·날짜 범위·실패 복구·터치/핀치·저장 브리지 검증을 진행했다. 브리지 저장은 모의 호출이며 실제 갤러리 쓰기는 아니다. 결과는 design-preview/verification/d2의 JSON과 캡처에 보관한다.

실제 사용자에게는 안내 전 ‘좋음→매우 좋음→좋음 복귀’, ‘현재 선택 모두 취소’, ‘이전 컷으로 복귀’, ‘저장 장수 설명’을 수행하게 하고 예상과 행동을 비교해야 한다. Undo의 문맥별 차이가 실제 사용자에게 충분히 드러나는지는 여전히 검증할 가설이다.
