# Photo Pick 페르소나 기반 가상 사용성 검토

검토일: 2026-10-09 (한국 시간)
형식: 세 에이전트가 각기 다른 페르소나로 이미지와 동작 명세를 읽고 수행 경로를 추론한 인지적 워크스루.
한계: 실제 참가자 인터뷰·터치·작업 시간·성공률을 측정하지 않았다. 새 제스처와 절충 화면은 미구현이다. 페르소나는 타깃 여성 전체를 대표하지 않는다. 아래 발견은 검증할 가설이며 기능 테스트 통과나 사용자 만족도 결과가 아니다.

## 공통 판단

기존 사진 전체 비율과 사진 밖 하단 바를 유지하고 제스처·코랄·하트·즐겨찾기를 추가하는 절충 방향이 타당하다는 가설이 나왔다. 좌우 탐색은 비슷한 컷 비교에 적합할 것으로 예상됐다. 상단 별뿐 아니라 하단 아주 좋음도 유지하면 한손으로 접근할 수 있는 대안이 된다. 실제 빠름·편안함·성공 여부는 이 검토로 판단할 수 없다.

### 1. 아주 좋음의 의도치 않은 강등 — 세 페르소나 모두 높은 위험

별을 켠 뒤 아래로 습관적으로 넘기면 좋음으로 낮아질 수 있다. 두 등급 모두 저장 대상이므로 결과 장수만 보아서는 강등을 알아차리기 어렵다. 초보는 즐겨찾기와 좋음을 독립 상태로 이해할 가능성도 있다.

권고: 사용자 아래=좋음 규칙을 임의 변경하지 않는다. 드래그 미리보기에서 기존 아주 좋음인 경우 ‘좋음으로 변경’을 분명하게 표시하고 놓기 전 취소할 수 있게 한다. 아주 좋음 보존 후 이동 예외는 별도 정책 후보로 실제 사용자 비교 과제에 넣는다. 높은 위험이라는 평가는 페르소나의 추론이다.

실제 과제: ‘이 사진을 아주 좋음으로 고른 뒤 다음 사진을 보세요.’ 조작 전에 결과를 예측하게 하고, 조작 뒤 별 유지/변경을 인지했는지 확인한다.

### 2. 재탭 취소와 Undo 없는 복구 — 공통 발견

오른쪽으로 복귀 → 활성 하트 재탭 경로는 명세상 성립하지만 ‘현재 상태 표시’가 ‘다시 눌러 해제’라는 의미임을 스스로 알기 어려울 수 있다. 사진작가는 중간, 초보는 높은 위험으로 평가했다.

권고: 첫 평가에만 ‘선택한 버튼을 다시 누르면 취소’를 짧게 안내한다. 활성 배경·채워진 아이콘·문구를 함께 사용하고 해제 후 현재 사진에 머문다. 별과 하단 아주 좋음은 동기화한다. 기존 사용자도 별도 평가 취소 행이 없어지는 변화를 이해해야 한다.

실제 과제: 취소 방법을 알려주지 않고 ‘방금 잘못 고른 사진을 선택 전 상태로 되돌려주세요.’ 복구 경로, 도움 요청, 다른 등급으로만 바꾸는 행동을 관찰한다.

### 3. 버튼과 아래 제스처의 이동 차이 — 초보/경험자 발견

동일한 좋음 평가인데 버튼은 머물고 아래는 다음으로 이동한다. 빠른 제스처와 상태 수정이라는 역할 차이는 설명 전에는 보이지 않을 수 있다. 초보가 버튼만으로 선택하면 과제 실패로 분류하지 않는다.

권고: 첫 사용에 ‘← 다음 · → 이전 · ↓ 좋음으로 고르고 다음’과 ‘버튼으로 현재 사진 평가 수정’을 단계적으로 짧게 알린다. 안내를 항상 띄워 사진을 가리지 않는다. 안내의 길이·위치는 실제 화면에서 확인한다.

실제 과제: 먼저 안내 없이 고르게 한 뒤 필요한 안내를 보여준다. 버튼 탭과 아래 드래그의 이동 결과를 각각 예상하게 한다.

### 4. 확대 팬과 평가 충돌 — 공통 주의, 조작 검증 필요

사진작가와 경험자는 표정·눈·초점을 확대해 비교한다. 확대 상태에서 한 손가락으로 아래 이동이 평가로 해석되면 실수 위험이 높다. 확대 상태에서 다음 사진 이동이 막힐 때도 모드가 드러나야 한다.

권고: 확대·두 손가락 상태에서는 평가/넘김 제스처를 차단하고 사진 팬만 처리한다. 기본 배율 복귀 수단을 명확히 둔다. 상단 이전/다음 버튼은 탐색 대안으로 유지하고 확대 상태에서의 버튼 동작·전환 뒤 배율을 구현 전 명세한다. 인접 컷 확대 위치 유지/비교 모드는 후속 후보다.

실제 과제: ‘세 사진의 눈과 초점을 비교해 가장 좋은 컷을 고르세요.’ 확대→팬→복귀→인접 이동에서 잘못 평가되는지 확인한다. 이미지로 성공 여부를 판단하지 않는다.

### 5. X의 의미와 저장 범위 — 초보/사진작가 발견

X는 삭제, 미평가, 별로 중 무엇인지 오해할 수 있다. 좌우로 넘긴 미평가와 X를 누른 별로는 다른 상태다. 현재 이미지는 저장 대상·위치까지 보여주지 않는다.

권고: X에 ‘별로’ 라벨 유지, 초기에는 모든 평가 비활성, 좌우 이동은 등급 불변. 첫 사용에 ‘평가해도 원본은 삭제되지 않아요’를 짧게 안내한다. 결과에는 좋음 n장·아주 좋음 n장과 저장 대상 합계를 표시한다. ‘선택 사진을 원본으로 저장’과 저장 완료 위치를 명확히 한다.

실제 질문: ‘X를 누른 사진과 그냥 넘긴 사진은 무엇이 다르죠? 파일은 어떻게 되죠?’ 이후 실제 저장 결과와 예상 범위를 비교한다.

### 6. JPEG 지원과 중단 후 복원 — 경험자 추가 발견

JPEG+RAW 촬영자는 ‘원본’이 RAW까지 포함된다고 해석할 수 있다. SD를 재연결하거나 앱을 닫았을 때 날짜·사진 위치·등급 모두 유지하기를 기대할 수 있다. 이 검토에서는 실제 불러오기·복원·저장 화면을 실행하지 않았다.

권고: 입력 단계에서 JPEG 전용을 알리고 가능한 범위에서 제외된 RAW 수를 알려준다. 저장 문구는 ‘선택한 JPEG 원본 저장 · 재압축 없음’. 이어하기는 기존 위치·범위·평가를 일관되게 복원하고 접근할 수 없는 파일은 평가 삭제와 구분한다.

실제 과제: JPEG+RAW 폴더를 넣고 지원 대상을 설명하게 한다. 중간 종료→카드 재연결→복귀를 수행한 뒤 무엇이 남아 있기를 기대했는지 확인한다.

## 다음 시안에 먼저 반영할 제안

1. 기존 다크 집중 화면·사진 전체비율·사진 밖 3분할바를 유지한다.
2. 첫 사용 안내는 제스처와 재탭 취소를 짧게 전달한다.
3. 아주 좋음에서 아래로 내릴 때 실제 변화가 드래그 중 드러나게 한다. 강등/보존 정책은 결정 항목으로 유지한다.
4. X는 별로이며 원본 삭제가 아님을 설명한다.
5. 상단·하단 아주 좋음 아이콘은 같은 별과 같은 상태를 쓴다.
6. 평가뿐 아니라 확대·결과·입력·이어하기 화면을 다음 검토 범위에 포함한다.

## 실제 사용자 테스트 기록 양식

각 과제에서 안내 전 예상, 첫 행동, 결과 이해, 잘못된 상태, 도움 필요 여부, 복구 경로를 기록한다. 작동하는 프로토타입에서만 완료 여부·소요 시간·오입력을 측정한다. 설명을 준 뒤의 수행과 설명 없이 발견한 행동은 분리한다. 사진작가와 타깃 초보/경험자의 결과를 한 평균 점수로 합치지 않는다.

현재 앱 파일과 배포는 변경하지 않았다. 이 기록은 다음 시안과 실제 검증을 위한 가설 목록이다.

## 검토 후 사용자 결정

2026-10-09: 아주 좋음은 아래 스와이프로 강등되지 않고 유지한다. 활성 아주 좋음 아이콘 재탭 또는 다른 평가 버튼의 명시적 입력으로만 해제/변경한다. 작은 되돌리기 아이콘을 하단에 추가한다. 최신 하단 구성은 [되돌리기] [별로 / 좋음] [매우 좋음 아이콘]이다. 이 결정은 위에 서술된 강등·Undo 없는 복구 시나리오의 이전 동작 전제를 대체한다. 새로운 정책의 실제 사용성 검증은 아직 하지 않았다.
