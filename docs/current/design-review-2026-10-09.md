# Photo Pick 최신 기획안 병렬 검토

검토일: 2026-10-09 (한국 시간)
출처: 사용자가 집 PC의 현재 대화에 전달한 회사 PC의 마지막 검토안.
기준 구현: Android 0.2.7 및 로컬 github-upload 소스.
상태: 기획 검토 및 제안. 사용자가 아래 권고안을 확정한 것은 아니며 앱 구현 변경은 하지 않았다.
검토 분야: UX·제스처, 비주얼·접근성, Android 구현·사진 처리. 세 에이전트 병렬 검토와 종합 판단.
이 문서는 프로젝트 폴더의 인수인계 기록이며 회사 PC 대화 원문 전체를 복구한 기록은 아니다.

## 사용자가 전달한 최신 방향

- Photo Pick: 카메라 사진 중 마음에 드는 장면을 빠르게 골라 원본으로 받는 앱. 비전문가 20~30대 여성, 여행·일상·행사 후 사진 선택. Android 10 이상, 현재 0.2.7.
- 폴더·SD카드·JPEG 불러오기 → 촬영일 선택 → 앨범/한 장씩 평가 → 요약 → 좋음·아주 좋음 원본 저장.
- 좌우 스와이프는 이전/다음 탐색, 아래 스와이프는 좋음 후 다음 사진. 아주 좋음 입력은 미결정.
- 방향별 카드 이동·색 오버레이·아이콘으로 결과 예고. 하단 버튼 유지, 잘못 넘기거나 평가했을 때 Undo, 평가 확정 시 짧은 햅틱과 모션.
- 별로(미평가)를 기본 상태로 구상. 단순 탐색은 평가하지 않음. 다운로드 대상은 좋음과 아주 좋음.
- 몰입형 사진 화면, 상하단 반투명 블러 UI, 다음 카드가 조금 보이는 스택. 상단 얇은 진행바·뒤로가기 아이콘·결과 아이콘과 선택 개수 배지. 하단 알약형 플로팅 바.
- 더블탭 및 핀치 확대. 얼굴 위치 자동 확대, 필름스트립은 후순위 검토.
- 블루에서 핑크기가 있는 코랄로 변경. 긍정 평가와 브랜드 포인트에만 코랄 사용, 부정 신호는 회색. 좋음은 연한 코랄, 아주 좋음은 진한 코랄 또는 골드 후보.
- 로고 뒤 점은 코랄. X·엄지·별 대신 하트·반짝임 후보. 따뜻한 톤, 다크 옵션·시스템 연동. 기본 밝은 테마 여부 미결정.
- 눈감음 감지 → 연사 묶음/베스트 컷 → 흔들림/초점 감지 순서의 스마트 기능. 2차로 미뤄도 됨.
- 요약 후 바로 저장, 오늘의 베스트 컷 공유 구상. 서버 사진 업로드 없음, 평가 시 원본 유지, 재압축 없이 저장. JPEG 전용 안내.
- SD 리더·카메라 Wi-Fi 전송 안내. 감성적인 카피, ‘사진은 많이, 선택은 가볍게’ 유지 가능.
- 미결정: 아주 좋음 입력, 왼쪽 넘김의 의미, 재방문 평가 수정, 기본 테마, 1차 범위.

## 핵심 검토 결과

### 평가와 탐색 상태를 구분해야 함

별로와 미평가는 의미가 다르다. 안 본 사진, 확인했지만 선택하지 않은 사진, 명시적으로 별로인 사진을 한 상태로 합치면 이어하기·완료·필터가 모호해진다.

권고: 새 기본 화면은 ‘미선택 / 좋음 / 아주 좋음’으로 표현하고 확인 여부는 별도 기록한다. 기존 0.2.7의 별로 등급은 데이터에서 보존한다. 등급을 확인 여부로 추정하거나 기존 미평가를 모두 확인 완료로 바꾸지 않는다. 명시적 별로 등급을 계속 쓸지는 사용자 결정 사항이다.

현재 review-ui.js는 평가 후 다음 미평가 사진으로 건너뛰고 끝에서 firstUnrated로 돌아간다. 새 탐색 모델은 선택한 날짜 범위에서 순서대로 다음 사진으로 이동하는 편이 일관적이다. 미평가만 보기/이어보기는 별도 명시적 모드로 둔다.

### 아주 좋음 제스처는 의견이 갈림

UX 에이전트는 위로 아주 좋음을 1차 후보로 제안했다. 종합 권고는 1차에서 아래=좋음, 아주 좋음=명확한 하단 버튼으로 시작하고 위 제스처는 사용자 검증 후 결정하는 것이다. Slidebox 공식 소개에서 위는 휴지통, 아래는 즐겨찾기로 안내하므로 익숙한 사용자에게 위=아주 좋음은 다른 의미가 된다. 이 사실만으로 위 제스처를 금지하는 것은 아니며 별도 안내와 테스트가 필요하다.

아래로 길게 끌기는 기준 거리 학습과 오입력 위험이 있다. 두 번 아래로 스와이프는 첫 입력 후 다음 사진 이동과 충돌하므로 제외 권고.

### Undo와 재평가

사용자가 요청한 ‘잘못 넘기거나 평가했을 때 복구’를 유지하려면 탐색과 평가를 구분하는 작업 이력이 필요하다. 평가 변경과 자동 다음 이동은 한 작업으로 기록한다. Undo는 최근 완료된 사용자 행동의 이전 위치·평가를 함께 복구하고 ‘사진 이동 되돌리기 / 평가 되돌리기’로 의미를 안내한다. 기존 UX 에이전트의 평가 전용 Undo 권고와는 다른 종합안이며 최종 정책은 미확정이다.

재방문한 사진은 기존 평가를 표시하고 수정·해제 가능하게 한다. 같은 평가를 반복 입력해도 선택 개수는 증가하지 않는다. 탐색만으로 평가를 삭제하지 않는다. 마지막 사진에서는 결과 진입을 안내하고 자동으로 첫 미평가로 순환하지 않는다. 요약 진입을 모든 사진의 평가 완료로 표현하지 않는다.

### 확대와 제스처 충돌

1배에서는 한 손가락 탐색·평가, 확대 상태에서는 사진 내부 이동만 처리한다. 두 번째 손가락이 닿으면 대기 중 스와이프 평가를 취소한다. 손을 놓기 전에는 미리보기만 보여주고 확정하지 않는다. 대각선·짧은 드래그·중도 취소는 평가하지 않는다.

더블탭은 누른 위치 중심 확대/원래 크기 복귀부터 시작한다. 얼굴 자동 확대는 2차로 둔다. 기존 ‘손을 떼면 원복’과 새 ‘더블탭 확대 유지’를 섞지 말고 확대 유지·종료 규칙을 별도로 확정해야 한다. 확대 중에는 평가 제스처를 막고 보조 버튼으로 선택하는 방식은 별도 명확히 정한다.

### 사진 화면과 코랄

화면 전체를 사용하되 기본 사진은 원본 전체 프레임과 비율을 보존한다. 가로 사진을 세로 화면에 꽉 채우려고 잘라내지 않는다. 스택은 현재 사진을 가리지 않는 작은 다음 카드 노출로 제한한다.

좋음은 하트와 문구, 아주 좋음은 반짝임과 문구로 구분한다. 코랄 농도만으로 등급을 표현하지 않는다. 코랄은 작은 라벨·가장자리·버튼에 우선 사용하고 사진 전체의 색을 물들이는 오버레이는 줄인다. 블러 뒤에는 가독성을 위한 표면 또는 스크림이 필요하다. 연한 코랄 버튼에 흰 글자를 기본으로 확정하지 않는다. 실제 색과 밝은/어두운 사진으로 대비를 계산해야 한다.

진행바는 현재 위치를 나타내고 선택 개수 배지는 별도로 둔다. 확인 비율로 표현할 경우 실제 확인 기록을 사용한다. 정확한 현재 위치는 접근성 이름 또는 탭 시 표시 등으로 제공한다.

기본 테마는 미확정이다. 비주얼 에이전트는 시스템 연동을 기본으로 권고했다. 종합 시안 후보는 시스템 연동·수동 선택 가능한 따뜻한 앱 화면과 어두운 중립 사진 평가 캔버스다. 밝은 사진 평가 화면과 비교한 뒤 확정한다.

작은 글자 대비 4.5:1, 필수 아이콘/상태 대비 3:1을 검증 기준으로 사용한다. Android 보조 버튼은 터치 영역 최소 48×48dp를 권장한다. TalkBack 이름·선택 상태, 이전/다음/확대 버튼 대안, 모션 감소 설정을 포함한다. WCAG는 웹 기준으로 참고하고 Android 화면은 실제 기기 접근성으로 별도 확인한다.

## 1차 범위 권고

포함: 기존 불러오기·촬영일·앨범·원본 저장을 유지하면서 좌우 탐색, 아래 좋음, 아주 좋음 버튼, 기존 평가 표시/수정/해제, Undo, 확대 동작 정리, 코랄 포인트, 짧은 피드백, 요약 및 이어하기.

후속: 얼굴 자동 줌, 필름스트립, 눈감음/연사/흐림 추천, 복잡한 카드 스택, 공유 카드 생성, 카메라별 직접 Wi-Fi 전송 구현. 1차 Wi-Fi 항목은 실제 지원하는 전송 방식의 안내로 한정한다.

‘갤러리보다 훨씬 빠름’과 특정 타깃의 선호는 검증 전 제품 가설이다. 같은 사진 묶음으로 기본 갤러리와 선택 시간·실수·복구·학습을 비교한다. 자연스러운 제스처라는 인상만으로 성공을 판정하지 않는다.

## Android 소스 검토 및 원본·프라이버시

현재 WebView + Java 네이티브 입출력 구조로 새 1차 흐름을 구현할 수 있다는 코드 검토 결과다. 실제 새 흐름을 구현하거나 실행해 검증한 결과는 아니다.

- 현재 저장 범위 기본은 best다. 새 기획의 좋음+아주 좋음을 기본으로 하려면 combined로 바꾸고 저장 직전 범위·장수 표시를 맞춰야 한다.
- 현재 Undo 이력은 매 평가마다 전체 등급 사본을 넣는다. 대량 사진에서는 이전 등급·위치·사진 ID·행동 종류의 작은 변경 기록을 제한된 개수로 유지하는 것이 낫다. 늦은 이미지 응답과 애니메이션 취소도 같은 작업 단위로 처리한다.
- 원본 내보내기는 MainActivity의 원본 스트림을 MediaStore에 복사한다. 화면용 미리보기의 JPEG 재압축과 내보내기의 원본 보존을 구분한다. 공유용 꾸밈 이미지를 만들 경우에도 원본 다운로드와 별도 행동으로 표시한다.
- 앨범 썸네일과 집중 사진에 별도 크기를 쓰고, 보이는 영역과 현재/이전/다음 사진 중심으로 디코드 캐시를 제한한다. 1차 카드 스택은 다음 한 장만 권고.
- 기존 EXIF GPS 장소명 조회는 Geocoder를 자동 호출하며 네트워크를 사용할 수 있다. 사진 파일 업로드 없음과 모든 관련 정보의 오프라인 처리는 다르다. 완전 기기 내 처리가 목표라면 1차 자동 장소명 조회 제외를 권고하고, 유지 시 위치 조회 안내와 사용 여부 선택을 명확히 한다. 이는 아직 사용자 결정이 아니다.
- 햅틱은 평가 확정 때 한 번만 주고 시스템 설정을 존중한다. 모션 감소는 단순 카드 교체로 대체해 기능을 유지한다.

## 구현 후 확인할 수용 기준

1. 좌우 탐색만으로 평가가 바뀌지 않는다. 아래 좋음/버튼 아주 좋음은 한 번만 기록되고 바로 다음 순번으로 이동한다.
2. 대각선 취소, 짧은 드래그, 두 번째 손가락 진입, 확대 팬, 연타, 중간 이탈에서 의도하지 않은 평가가 발생하지 않는다.
3. 재평가 및 Undo 후 사진 위치·등급·선택 개수·요약·저장 목록이 일치한다. 끝에서 자동 순환하지 않는다.
4. 기존 0.2.7 평가를 마이그레이션한 뒤 좋음·아주 좋음·별로 기록을 잃지 않는다. 미평가를 확인 완료로 추정하지 않는다.
5. 어두운/밝은/복잡한 사진, 세로/가로, 큰 글자, TalkBack, 모션 감소에서 사진 전체와 조작부가 보인다.
6. 실물 SD리더의 큰 JPEG 1,000장으로 로딩·탐색·메모리·중단을 측정한다. 저장 공간 부족·리더 분리·재시도를 확인하고 내보낸 원본의 SHA-256을 비교한다.
7. 새 기획의 빠르고 가벼운 선택 경험은 타깃 사용자 관찰로 검증한다. 이번 에이전트 검토를 사용자 조사 결과로 표현하지 않는다.

## 다음 작업 시작 시 확인

이 문서를 최신 기획 검토 기록으로 먼저 읽는다. 이전 design-direction.md의 좌=별로/우=좋음/위=아주 좋음이나 0.2.7의 스와이프 없음 정책을 새 기획의 최종 결정으로 오인하지 않는다. 새 제스처·등급·테마는 사용자 승인 전 권고안이다. 실제 구현은 별도 요청 후 진행한다.
