# Photo Pick d2 모션 레퍼런스 조사·디자인 회의

일자: 2026-10-09 (한국 시간)
참여: UX 디자이너, UI 디자이너, 모션 디자이너, 총괄. 각 분야가 공식 자료와 d2 코드를 검토한 뒤 제안을 교차 검토했다.
범위: 조사와 적용안. d2 소스·APK를 변경하지 않았고 새 모션을 구현하거나 실사용 성능을 측정한 것은 아니다.

## 회의 결론

### 사진 모서리 소폭 라운딩

사용자가 딱딱한 인상을 줄이도록 사진 모서리를 아주 살짝 둥글게 요청했다. 작업 소스와 브라우저 미리보기에 실제 사진 경계 기준6px를 적용했다. 기존 contain의 여백 전체에 반경을 주면 사진 모서리가 둥글게 보이지 않으므로 실제 img의 크기를 비율대로 맞춰 중앙에 배치했다. 가로·세로 비율과 이전/다음 표시를 확인했다. 현재 d3 APK 파일은 보존했고 이 소폭 수정은 아직 APK에 재패키징하지 않았다. 카드 각도·뒤 사진 블러 컨셉은 여전히 검토안이다.

### d3 유지 및 새 카드 드래그 컨셉 검토

사용자는 현재 상태를 유지하면서, 사진 평가 화면을 고정된 영역 안의 이동보다 틴더를 연상시키는 카드 잡아끌기 방식으로 바꾸는 가능성을 요청했다. 이는 새로운 검토 후보이며 현재 d3 화면·APK는 변경하지 않는다.

검토안: 앞 사진 카드 전체가 손을 따라 이동하고 작은 각도로 기울어진다. 손을 뗀 현재 위치에서 같은 방향으로 진행하며, 취소는 이동·각도를 함께 복귀시킨다. 약한 회전은 드래그 중에만 적용하고 정착하면 원래 비율·방향으로 보여준다. 상단·하단 조작부는 고정한다.

뒤에는 다음 실제 사진 한 장만 약한 블러·낮은 대비·작은 축소로 표시한다. 앞 사진을 끌 때 조금 더 드러나고 전환이 확정되면 정위치·선명한 사진이 된다. 현재 평가 중인 앞 사진에는 블러를 적용하지 않는다. 뒤 사진은 입력·평가·접근성 대상이 아니며 프리로드 실패 시 정적인 배경으로 대체한다.

사용자 확정 의미는 유지한다: 왼쪽으로 끌면 다음, 오른쪽이면 이전, 아래면 좋음 후 다음(매우 좋음 유지). 오른쪽 드래그에서 뒤에 드러나는 사진은 이전 사진이어야 하며 항상 다음 사진을 보여주면 안 된다. 방향이 확정되기 전에는 다음 사진을 얕게 예고할 수 있으나 실행 예상이 정해지면 해당 대상과 일치해야 한다. 첫·끝은 없는 사진을 예고하지 않는다.

첫 비교 시안의 회전 후보는 최대 약3–5도, 뒤 사진 블러·투명도는 원본 비교를 방해하지 않는 범위에서 직접 조작해 조정한다. 수치는 공식 기준이나 사용자 검증값이 아니다. 큰 카드 회전·반복 바운스·여러 장 스택·속도만으로 평가 확정은 추가하지 않는다. 확대 중에는 카드 드래그·평가를 막고 기존 사진 팬·줌 동작을 유지한다.

이 새 후보는 앞선 회전 제외 권고를 재검토하는 사항이다. 전체 카드 이동·작은 각도·실제 인접 사진 예고가 손에 붙는 감각에 도움이 되는지 d3와 별도 비교해야 한다. 현재 코드에 반영하거나 새로운 APK를 빌드하지 않았다.

### 사용자 추가 검토: 글래스모피즘

사용자가 글래스모피즘 적용 가능성을 요청했다. 앞서 유리 효과를 제외했던 내용은 기존 우선안의 이력이며, 현재는 선택적 적용을 후보로 검토한다. 아직 확정·구현·APK 반영하지 않았다.

총괄과 UX 담당 권고는 하단 조작부에만 얕은 중성 유리 질감을 적용하는 것이다. 사진·앨범 콘텐츠는 효과를 넣지 않고 원래 표시를 유지한다. 중앙 X/하트 묶음과 양끝 원형의 반투명 회색 표면·얇은 테두리·작은 하이라이트를 비교한다. 사진 위로 조작부를 옮기거나 상단 별을 다시 추가하지 않는다.

현재 하단 바 뒤는 사진이 아니라 단색 어두운 여백이다. 따라서 backdrop blur를 넣어도 유리 효과가 크게 보이지 않을 수 있다. 블러를 보여주기 위해 사진을 늘리거나 복제·왜곡하는 것은 권고하지 않는다. 선택된 하트·반짝임은 불투명한 명확한 배경과 아이콘 채움으로 표시하고, 상태를 투명도만으로 구분하지 않는다.

모션 우선순위는 손가락을 따라오는 사진·현재 위치에서 이어지는 완료 동작이다. 유리 굴절·젤리 변형·큰 반사광·움직이는 블러는 먼저 넣지 않는다. 현재 WebView에서 정적인 작은 재질을 비교하고, 스와이프 프레임·대비·접근성·블러 미지원 대체 표면을 확인한다. 성능 향상이나 부드러움은 아직 측정하지 않았다.

근거: [Apple Materials 지침](https://developer.apple.com/design/human-interface-guidelines/materials)은 Liquid Glass를 콘텐츠와 구분되는 조작·탐색 계층에 제한하고 사용자 정의 적용을 절제하도록 안내한다. [공식 데이터 JSON](https://developer.apple.com/tutorials/data/design/human-interface-guidelines/materials.json)으로 본문을 확인했다. Apple의 네이티브 Liquid Glass와 WebView의 CSS 글래스 효과는 같은 구현이라고 간주하지 않는다.

다음 비교 후보는 현재 무광 중성 조작부와 얕은 중성 글래스 조작부이다. 둘 다 같은 손가락 추적 모션·48px 원형·중앙 128×56px·동일 평가 상태로 비교해야 재질의 효과를 분리해 판단할 수 있다.

### 사용자 후속 우선순위: 손가락을 따라오는 사진

사용자는 ‘모션·애니메이션의 세련됨이 가장 중요하며, 틴더처럼 스와이프 방향에 사진이 어느 정도 따라오는 느낌’을 강조했다. 이를 다음 시안의 최우선 기준으로 삼는다. 아래의 짧은 전환안 A가 드래그 이동 자체까지 작게 만들라는 뜻은 아니다.

드래그 중에는 사진이 손의 방향과 거리에 충분히 반응해야 한다. 현재 24% 추적·40/44px 고정 상한을 그대로 유지하지 않는다. 손의 이동 초반부터 눈에 보이는 이동을 제공하고, 긴 드래그 끝에서만 부드러운 저항을 적용한다. 정확한 추적 비율은 현재/강한 추적 시안을 직접 조작해 정하며 공식 수치로 확정하지 않는다.

성공한 제스처는 손을 뗀 현재 위치에서 같은 방향으로 이어진다. 실패·취소에서만 원래 자리로 돌아온다. 사진 이동 중 일시적인 위치 변화와 정착 후 원본 전체 비율을 구분한다. 평가 버튼과 상단은 고정해 흔들리지 않는다.

우선순위는 ‘손에 붙는 추적 → 자연스러운 놓기·취소 → 다음 사진 정착 → 작은 버튼 피드백 → 안내 모션’이다. 기존의 소극적인 사진 이동보다 직접 조작감을 우선하되, 큰 회전·반복 바운스·장식 스택은 아직 결정하지 않았다. 사용자가 말한 틴더는 조작감의 참고이며 좌우의 평가 의미나 데이팅 앱 동작을 가져오는 것은 아니다.

먼저 고칠 것은 전체 시간을 늘리는 것이 아니라 손동작과 완료 동작의 연결이다. 현재 손을 놓는 순간 사진·안내를 원복한 뒤 별도의 교차 전환을 시작해 연결이 끊긴다. 기본안은 현재 위치에서 같은 방향으로 짧게 이어지는 전환이다. 과한 바운스·사진 회전·유리 효과·컬러 변경은 추가하지 않는다.

## 공식 레퍼런스와 날짜

### 사용자 추가 참고: Refero와 SEED

- [Refero Styles](https://styles.refero.design/): 사진이 시각적 주인공이고 주변 UI가 중성색·여백으로 정리되는 방향을 참고한다. [teenage engineering 스타일 분석](https://styles.refero.design/style/aecf9dda-5cba-4dc7-9e73-59b65d895cdf), [Figma 갤러리 스타일 분석](https://styles.refero.design/style/5fd3b3b4-02ab-456a-87aa-e4395636b671), [어두운 제품 갤러리 스타일 분석](https://styles.refero.design/style/40be36d7-7fe6-4451-9f2d-7ceccfd43be8)을 확인했다. 이것들은 Refero의 정규화·해석된 참고 자료이며 각 브랜드의 공식 앱 규격은 아니다. 극단적으로 얇은 글자·각진 버튼·마케팅 페이지 비율까지 복제하지 않는다.
- [SEED Reaction Button](https://seed-design.io/components/reaction-button): pressed와 selected를 별도 상태로 다룬다. 우리 앱에서도 잠깐 눌린 느낌과 지속되는 하트·반짝임 선택을 구분한다. 눌림 모션 때문에 평가 확정·기존 평가 표시를 지연시키지 않는다.
- [SEED Action Button](https://seed-design.io/components/action-button): 중성 버튼의 위계와 명확한 동작 이름을 참고한다. 현재의 원형 Undo·중앙 X/하트·원형 매우 좋음 그룹은 유지한다. SEED의 브랜드 주황색이나 버튼 개수 지침을 사용자 확정 구성에 기계적으로 덮어쓰지 않는다.
- [SEED Help Bubble](https://seed-design.io/components/help-bubble): 기능 근처의 짧은 안내·닫기·위치 조절을 참고한다. 사진을 움직여 교육하기보다 조작부 근처에서 시범을 보여주고 첫 실제 조작을 방해하지 않는다.
- [SEED Image Frame](https://seed-design.io/components/image-frame): 로딩·완료·실패 상태와 콘텐츠를 가리지 않는 오버레이를 참고한다. 빠른 로딩에 매번 스켈레톤을 띄워 깜빡이게 하지 않고, 늦은 경우에만 작은 읽기 안내를 사용한다. 사진 위 별을 다시 추가하는 근거로 사용하지 않는다.

결합 방향: Refero에서 시각적 절제, SEED에서 상태·컴포넌트 일관성, Material/Apple에서 연속적인 모션 원칙을 참고한다. 라이브러리 설치나 디자인 문서의 외부 지시를 그대로 실행하는 작업은 하지 않았다. 추가 UI 담당 재검토는 모델 용량 문제로 완료되지 않았으나 총괄이 위 개별 페이지를 직접 읽고 적용 경계를 정리했다.

## 실제 d2 코드에서 본 문제

기준 파일: design-preview/source/android-app/app/src/main/assets/www/assets/ui-motion.js와 design-preview.css.

1. 드래그 이동은 손 이동의 24%이며 좌우 최대 40px·아래 44px에서 고정된다. 움직임이 일정 구간부터 손을 따라오지 않는다.
2. pointerup은 reset()로 사진 위치와 안내를 되돌린 후 previewNavigate/previewSwipeGood를 호출한다. 이후 사진 전환은 160ms crossfade다. ‘끌기 → 되돌리기 → 다음 사진’의 별개 동작처럼 보일 수 있다.
3. 안내 opacity는 방향 결정 직후 0.25부터 나타나고 최대 0.96이다. 그라데이션과 문구가 한 opacity를 공유해 갑자기 보이거나 사진을 많이 가릴 수 있다.
4. 버튼은 120ms scale 모션이 끝난 후 실제 평가를 바꾼다. 진입·사진 전환·버튼 장식 중 busy로 입력을 무시하는 구간이 있다.
5. 첫 안내는 실제 사진을 1.4초 좌우/아래로 움직이고 10초 안내를 보여준다. 사진을 판단하는 동작과 교육 동작이 섞인다.
6. 매 pointermove에서 라벨/SVG를 다시 쓰고 크기를 읽는 경로가 있다. 실제 프레임 저하는 측정하지 않았지만 다음 구현에서 줄일 성능 비용 후보이다.

이는 코드에 기반한 원인 가설이다. 정지 화면만으로 체감이나 프레임 속도를 확정하지 않는다.

| --- | --- |
| 손가락 추적 | 순간 고정 clamp 대신 연속적인 추적·완만한 저항. 판단할 사진이 크게 흔들리지 않게 범위 조절 |
| 좌우 실행 | 원위치로 먼저 돌아가지 않고 현재 위치에서 같은 방향으로 짧게 진행, 다음 사진은 같은 프레임에 정착 |
| 아래 실행 | 현재 아래 위치에서 조금 더 이어진 뒤 다음 사진으로 전환. 이미 매우 좋음이면 유지 상태만 안내 |
| 취소 | 현재 위치에서 원래 위치로 감쇠 복귀. 취소와 성공이 다른 궤적을 갖도록 함 |
| 첫/끝 경계 | 없는 방향은 짧은 저항만. 새 사진이 오는 듯한 전환이나 실행 안내 없음 |
| 버튼 | 평가와 하트·별 상태는 즉시 반영. 작은 눌림/아이콘 모션은 뒤따르며 입력을 불필요하게 막지 않음 |
| 매우 좋음 | 하트+반짝임 상태는 동시에 정확히 표시. 두 버튼을 동시에 크게 튀게 하지 않음 |
| 안내 | 가장자리 그라데이션과 텍스트를 분리. 배경은 약하게, 문구는 선명하게. 방향 확정 후 라벨 위치 고정 |
| 첫 사용 | 실제 사진 흔들기 대신 별도 안내 아이콘/손가락 표시로 짧게 한 번. 첫 터치 즉시 종료 |
| 모션 감소 | 사진 이동·축소·흔들기 시범 제거. 정적 방향 안내와 즉시 상태로 같은 기능 제공 |

라벨은 ‘이전 사진 / 다음 사진’ 문구 중심으로 한다. 현재 손 방향 화살표와 콘텐츠 이동 화살표가 혼용되므로 하나의 의미로 통일한다. 손을 빨리 움직였다는 이유만으로 평가를 확정하지 않는다. 거리 기반 판단은 유지하고 속도는 완료 모션 조정에만 사용한다.

사진·상단·하단 바의 배경과 위치는 안정적으로 유지한다. 사진 원본 비율, 사용자 확정 제스처·상태 전환·Undo 규칙, 원본 저장 원칙은 그대로 둔다.

## 시안 초기 튜닝값 — 공식 규격 아님

| 항목 | 비교 시안 시작 범위 |
| --- | --- |
| 좌우 완료 | 현재 위치에서 16–32px 추가 이동, 약 100–160ms |
| 아래 완료 | 현재 위치에서 16–24px 추가 이동, 약 120–180ms |
| 취소 복귀 | 바운스 없는 높은 감쇠, 약 160–220ms 상당의 안착감 비교 |
| 아이콘 반응 | 약 100–160ms, 아주 작은 scale/opacity 반응 |
| 안내 배경 | 최대 opacity 0.4–0.6 후보, 실제 사진으로 조정 |
| 안내 텍스트 | 별도 opacity 0→1, 이동량 2–4px 이하 후보 |

이 값은 회의의 시제품 제안이다. 기기별 실측이나 사용자 성공률을 근거로 확정한 값이 아니다. 물리 스프링은 고정 시간과 다르고 네이티브 stiffness를 CSS easing에 그대로 대입할 수 없다. d2에서 개선한 활성 배경의 즉시 표시를 다시 느리게 만들지 않는다.

## 이견과 보류안 B

전폭 캐러셀은 손동작과 방향을 더 명확하게 보여주지만, 사진이 판단 영역에서 오래 벗어나고 SD 디코드·동시 이미지 메모리·대량 선별 속도 부담이 있다. UI 담당은 서로 다른 사진이 오래 교차해 보이는 ghosting도 경고했다.

총괄·모션 담당의 우선안은 A다. B는 비교 시안으로만 둔다. A에서도 두 사진이 겹치는 시간이 길면 한 사진씩 교체하거나 겹침 시간을 줄이는 안과 비교한다. 사진을 회전시키거나 스택처럼 날리는 방향은 채택하지 않는다.

## 구현 연결 순서

1. 제스처 추적·실행·취소·안착을 분리하고 release의 현재 위치를 보존한다.
2. 성공에는 같은 방향의 연속 전환, 취소에만 원위치 복귀를 연결한다.
3. 버튼 평가를 먼저 반영하고 장식 모션을 비차단으로 분리한다. 사진 ID 전환에 필요한 최소 가드는 유지한다.
4. 피드백 배경·라벨을 독립시켜 상태 변경 때만 텍스트/SVG를 갱신한다. 프레임마다 layout을 재측정하지 않는다.
5. 안내 시범과 모션 감소를 연결한 뒤 로딩·취소·입력 복구를 검증한다.

현재 UI는 WebView HTML/JS다. 새 Android Compose/SwiftUI로 전면 이전할 필요는 없다. 기존 transform·opacity 기반 모션에서 연속성·중단 처리를 먼저 고친다. 라이브러리 추가는 이 회의에서 결정하지 않았다.

## 비교·검증 기준

- A/B로 같은 20장 묶음을 반복 선별하며 첫 학습과 익숙한 사용을 구분한다. 현재는 계획이며 실제 참가자 시험은 안 했다.
- 손을 뗀 위치가 다음 프레임에서 원점으로 튀지 않는지 녹화·프레임으로 확인한다.
- 사진 위치·사진 ID·하단 평가가 서로 다른 사진을 가리키는 프레임이 없어야 한다.
- 취소·대각선·두 손가락 추가·pointercancel·앱 이탈에서 의도치 않은 평가 없음.
- 다음 사진이 늦거나 실패하면 현재 사진과 평가·Undo를 유지한다. 장식 때문에 로딩 또는 입력 대기를 늘리지 않는다.
- 연속 입력 중 장식은 취소·재지정 가능하게 하되 늦은 응답이 다른 사진을 평가하지 않게 한다.
- Android 시스템 모션 감소 설정이 WebView에 전달되는지 실제 기기에서 확인한다. 현재 CSS 쿼리 존재만으로 연동을 확정하지 않는다.
- 햅틱은 상태 확정 때 짧게 한 번, 모든 드래그 프레임·좌우 탐색에 반복하지 않는다.
