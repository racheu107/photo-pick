# Photo Pick 작업 정리 — 2026-10-12

현재 기준은 디자인 앱 **0.2.27 d21 / versionCode 30**. 과거 기록에 있는 기능과 현재 앱에 남아 있는 기능을 구분한다.

## 현재 적용 상태

| 구분 | 현재 동작 |
| --- | --- |
| 평가 | 별로·좋음·매우 좋음. 평가 확정 후 선택한 촬영일 범위의 다음 미평가 사진으로 이동 |
| 평가 수정 | 같은 좋음·별로를 다시 누르면 평가 해제 후 현재 사진 유지. 같은 매우 좋음을 다시 누르면 좋음으로 변경 |
| 초기화 | 왼쪽 원형 버튼은 현재 사진 평가 초기화. 직전 작업 복원과 구분 |
| 탐색 | 왼쪽은 다음 사진, 오른쪽은 이전 사진. 탐색만으로 등급 변경 없음 |
| 아래 드래그 | 좋음 평가 후 다음 미평가로 이동. 이미 매우 좋음이면 유지 |
| 확대 | 손을 놓아도 확대 유지, 한 손가락 팬, 더블탭·전체 보기로 복귀. 다음 사진은 전체 보기 |
| 사진 스택 | 다음 사진들을 위쪽에 작고 연하게 겹침. 뒤 카드 블러 유지, 배경용 이미지는 프레임을 채움 |
| 좌우 모션 | 하단 중앙 축, 최종 ±22.5도 회전. 드래그 중 최대 7% 축소, 확정 퇴장 시 90% 크기 |
| 아래 모션 | 드래그 중 최대 8% 축소, 실제 평가 버튼을 향해 작아지고 회전하며 흡수 |
| 버튼 | 초기화 원형 / X·하트 캡슐 / 매우 좋음 원형. 그래파이트·유리 느낌, 사진보다 위 레이어 |
| 버튼 반응 | 누른 아이콘만 3% 수축. 사진 도착 마지막 구간에 복귀·국소 강조 |
| 사진 정착 | 앞 사진 퇴장 후 뒤 사진이 앞자리로 이동. 확대된 배경 구도에서 전체 사진 구도로 블러와 함께 연결 |
| 첫 안내 | 어두운 오버레이·흰 문구·화살표·실제 작동 없는 사진 시연. 좌우·아래 및 버튼의 같은 기능 안내. 건너뛰기·다음·시작하기 제공 |
| 저장 | 등급 범위로 선택한 JPEG 원본 복사. SD 원본을 삭제하거나 이동하지 않음 |
| 제거한 기능 | 베스트샷 최종 N장 선택·A/B 비교. d14에 추가했다가 d15에 제거 |
| 미구현 아이디어 | 자동 태그·메모·유사 사진 묶기·얼굴 바로 확대 등은 검토만 진행 |

## 결정하고 적용한 흐름

1. **후보에서 최종 사진을 고르는 기능 검토 → d14 적용.** 평가 결과의 다운로드와 베스트샷 고르기를 분리하고, 매우 좋음·좋음 후보에서 여러 장을 선택하도록 구성. 모바일 A/B는 기본 A, 누르는 동안 B로 비교.
2. **사용 후 평가 중심으로 단순화 → d15.** A/B만으로 최종 사진을 고르기 어렵다는 사용자 판단에 따라 최종 선택 기능 제거. 평가 후 다음 미평가로 자동 이동하고 버튼 확대.
3. **확대 동작 결정 → d16.** 놓으면 복귀하는 방식과 유지하는 방식을 UX 사례로 비교하고 확대 유지 채택. 팬·더블탭·전체 보기로 검사 흐름 정리.
4. **사진 디자인·모션 방향 결정 → d17.** 디자인·모션 에이전트와 사용자 스케치를 바탕으로 위쪽 계단식 서랍 스택, 작은 뒤 카드, 버튼으로 흡수되는 앞 사진 구성. 넘기는 동안 뒤 카드 블러 유지.
5. **버튼 형태 확정 → d18.** 통합 바 대신 초기화 원형·X/하트 캡슐·매우 좋음 원형. 사용자 레퍼런스의 색과 유리 블러 반영.
6. **좌우 퇴장·배경 구도 조정 → d19.** 하단 중앙을 축으로 끝에서 20~25도 기울도록 요청받아 ±22.5도 적용. 뒤 사진은 프레임을 채우게 조정.
7. **UX in Motion 스타일 검토 → d20.** 별도 장식을 늘리기보다 버튼·사진·다음 카드의 반응을 연결. 누른 아이콘 수축, 도착 시 복귀, 뒤 카드 공급과 앞 사진 정착 연결.
8. **드래그 축소·첫 안내 시연 → d21.** 좌우·아래 조작 중 사진 자체도 축소. 첫 안내는 글상자 대신 오버레이와 사진 시연으로 교체하고, 같은 기능의 드래그·버튼을 함께 안내.
9. **추가 기능 탐색.** 개발자·기획자·가상 사용자 에이전트가 태그·메모·유사 사진 묶기 등을 검토. 풍경 속 작은 사람처럼 사용 의도와 자동 인식이 다른 경우를 고려해 자동 분류는 아직 적용하지 않음.

위 순서는 기능·디자인 결정의 흐름이며 반복 수정이나 검사 실행 순서는 생략했다. 가상 사용자·디자인 에이전트 검토는 실제 사용자 조사 결과가 아니다.
