# Photo Pick 오프닝 속도 회의 — d11

2026-10-09 · 모션/UX, UI/브랜드 디자인 역할 에이전트와 두 사용자 페르소나가 제안·교차 검토했습니다.

이 평가는 **AI 페르소나의 가상 인지 워크스루**입니다. 실제 참가자를 모집하거나 반응을 측정한 소비자 실험은 아닙니다. 아래의 사용자 인상은 시나리오 추론이고, 구현 검증은 별도의 브라우저 검사입니다.

## 확인한 문제

현재 d10은 로고가 620ms부터 나타나 950ms에 완성되지만, 1050ms부터 사라집니다. 완성된 이름을 볼 시간이 100ms뿐입니다. 반면 홈 화면이 희미한 상태는 550ms 유지됩니다. 전체 1.86초를 단순히 늘리기보다, 브랜드를 읽는 시간과 실제 화면을 여는 시간을 재배분하기로 했습니다.

## 가상 사용자 평가

| 페르소나 | 가정한 상황 | 예상되는 어려움 | 반영한 의견 |
| --- | --- | --- | --- |
| 27세 첫 사용자, 여행 사진을 찍는 비전문가 | 처음 설치해 카메라 이미지와 앱 이름을 처음 접함 | 카메라를 알아보는 동안 효과가 겹치고, 이름이 완성되자 곧 사라져 읽을 여유가 부족할 수 있음 | 카메라 → 빛 → 로고 순서를 정리하고 완성 상태 350ms 확보 |
| 31세 반복 사용자, 여행 사진 300장을 나눠 고름 | 앱을 여러 번 실행하며 바로 작업을 시작하고 싶음 | 홈이 터치 가능하지만 흐릿하게 보여 준비가 끝났는지 판단하기 어려울 수 있음 | 홈 페이드를 280ms로 단축하고 스킵·내부 복귀 미재생 유지 |

두 페르소나 모두 제안된 타임라인에 찬성했습니다. 이는 실제 사용자 선호도나 통계가 아닙니다.

## 합의한 타임라인

아래 시간은 자산 준비 후를 기준으로 합니다.

| 요소 | 시작 지연 | 실행 시간 | 완성 시점 |
| --- | ---: | ---: | ---: |
| 흰색에서 카메라 등장 | 100ms | 650ms, linear | 750ms |
| 접사에서 전체 구도로 이동 | 0ms | 950ms, 기존 감속 곡선 | 950ms |
| 렌즈 빛 | 350ms | 400ms | 750ms |
| 로고 | 750ms | 250ms | 1000ms |
| 카피 | 800ms | 200ms | 1000ms |
| 완성된 카메라·로고 유지 | 1000ms | 350ms | 1350ms |
| 오프닝 종료 페이드 | 1350ms | 220ms | 1570ms |
| 홈 페이드인 | 1570ms | 280ms | 1850ms |

전체는 1.86초 → **1.85초**로 거의 같습니다. 카메라 이미지를 서서히 보여주면서, 로고를 읽을 여유와 홈의 선명함을 함께 확보하는 방향입니다.

UI 검토에서는 마지막 줌이 감속하며 끝나는 점을 확인했습니다. 카피의 부모·자식 opacity가 중첩되지만 둘 다 1000ms에 완전히 표시되므로, 마지막 350ms는 로고와 카피가 선명하게 유지됩니다. 추가 효과나 오브젝트는 넣지 않았습니다.

## 구현 검증과 한계

브라우저에서 각 지연·실행 시간, 1000ms의 로고·카피 opacity 1, 홈의 280ms 페이드, 스킵, 입력 복구, 모션 감소, 내부 이동 시 미재생을 확인했습니다. APK 빌드·lint·서명 및 웹 자산 일치 검증도 통과했습니다.

기존 운영 앱과 d1~d10 APK는 해시가 변하지 않았습니다. 새 테스트 앱은 0.2.17 d11입니다. 실제 휴대폰 성능과 실제 이용자의 반응은 아직 검증하지 않았습니다.
